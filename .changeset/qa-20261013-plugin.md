"@loopress/wordpress-plugin": patch

API route and hook files are now syntax-checked with PHP's own parser before they are written, so a broken file is refused at push time on every host, Local by Flywheel and managed hosts included, instead of only where a `php` binary is on the PATH. A menu item pointing at a page or term missing on the site answers 422 instead of 500, and an empty menu item description no longer reads back as a single space, which showed as drift after every push. A static page holding an empty enclosing shortcode (`[tabs][/tabs]`) that runs `the_content` on its inner text no longer recurses until a 502: a nested `the_content` run for the page being rendered gets nothing back instead of the page. A form in the trash now counts as gone for `lps form push`, which recreates it, instead of updating it in the trash and reporting a successful push. A Composer sync with no package at all, on a site that never had one, no longer fails with a 500 ("require : Array value found, but an object is required"): an empty `require` is written as `{}`.
